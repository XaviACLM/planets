STYLE & PROJECT RESTRUCTURING PLAN
===================================

This document outlines a planned restructuring of the codebase, focusing on
migrating to Tailwind CSS and general cleanup/reorganization.


TAILWIND MIGRATION
------------------

Goal: Move styling to Tailwind where possible, with pragmatic exceptions.

What CAN be Tailwind-ized:
- All general layout (flex, grid, spacing, sizing)
- Most component styling (borders, colors, backgrounds, typography)
- Hover/focus states on buttons and simple interactive elements
- The settings menu dropdowns (currently using inline selectStyle objects)

What should STAY as separate CSS:
- Custom checkbox styling in SettingsMenu.css
  - Uses ::before to draw fake checkbox box
  - Uses ::after to draw checkmark on :checked
  - Uses adjacent sibling selector (.custom-checkbox + label)
  - Tailwind CAN do this with peer/before:/after: but it's painfully verbose
  - Pragmatic choice: keep this in its own small CSS file

What should STAY as inline styles:
- Dynamic SVG rendering (e.g., DominanceChart bar charts)
  - Computed values like: x={width - spacing - barWidth}
  - Transforms like: transform={`translate(0, ${i*symbolSize})`}
  - This is expected and natural - Tailwind is for static layout, not computed graphics

Custom utilities to add in index.css:
- .small-caps { font-variant: small-caps; }
  - Tailwind doesn't have a built-in utility for this
  - Used throughout DominanceChart and possibly elsewhere for stylized text

APPROACH FOR THE RESTRUCTURING
------------------------------

Suggested order:
1. Install and configure Tailwind
2. Add custom utilities (small-caps) to index.css or tailwind config
3. Migrate components one by one, starting with simpler ones
4. For each component:
   - Convert inline styles to Tailwind classes
   - Convert component CSS to Tailwind (except checkbox pseudo-elements)
   - Remove/consolidate any redundant or overriding styles
5. Clean up App.css - extract what's truly app-level vs what leaked in
6. Reorganize file structure into folders
7. Split astroDefs.ts into logical files

Keep in mind:
- User admits to "winging it" with CSS, so expect inconsistencies
- Some styles may be dead code or overridden elsewhere
- The project is an astrology app with zodiac wheel visualization
- SVG-heavy components are expected to keep inline styles for positioning
