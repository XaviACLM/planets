Routing & Chart Type Abstraction Plan
======================================

Goal: Split the app into multiple routes (landing, event chart, natal chart,
future return chart) with a generic chart page that doesn't know about chart types.

## New files
- src/App.tsx              — NEW (router + landing page, replaces current App)
- src/ui/SingleChartPage.tsx — RENAME of current App.tsx
- src/ui/LandingPage.tsx   — simple page with buttons to /event, /natal
- src/hooks/useEventChartInputs.ts  — hook for event chart date/city logic
- src/hooks/useNatalChartInputs.ts  — hook for natal chart (identical for now, different placeholder)

## Modified files
- src/main.tsx             — wrap App in BrowserRouter
- vite.config.ts           — make base path configurable via env var

## New dependency
- react-router-dom

## Architecture

### Chart input hooks

Each chart type provides a hook that returns a uniform interface:

    interface ChartInputs {
        selectedDate: Date;
        selectedCity: CityData | null;
        timezone: string;
        PickerBar: React.FC;       // date/city picker for the main sidebar
        WelcomeModal: React.FC<{ onProceed: () => void }>;  // modal content
    }

useEventChartInputs():
    - Owns selectedCity, selectedDate, currentTimezone state (moved from current App)
    - PickerBar renders CitySelector (placeholder "Enter location...") + DateTimePicker
    - WelcomeModal renders the existing WelcomeModal component, wired to the same state

useNatalChartInputs():
    - Identical to event, but CitySelector placeholder is "Enter birth location..."
    - WelcomeModal text could also differ later ("Enter birth date/location")

Both hooks internally own the same state. The PickerBar and WelcomeModal components
they return are closures over that state — they're already wired up. SingleChartPage
just renders them in the right slots.

### SingleChartPage.tsx (renamed from App.tsx)

Accepts a single prop:

    interface SingleChartPageProps {
        useChartInputs: () => ChartInputs;
    }

At the top of the component, calls the hook:

    const { selectedDate, selectedCity, timezone, PickerBar, WelcomeModal } = useChartInputs();

Then the rest of the component is identical to current App.tsx, except:
    - selectedCity/selectedDate/currentTimezone are no longer local state — they come from the hook
    - pickerBar becomes <PickerBar />
    - modal becomes <WelcomeModal onProceed={() => setShowModal(false)} />
    - showModal state stays in SingleChartPage (it's layout concern, not chart-type concern)
    - Everything else (aspects, zodiac wheel, settings, layout branches) is unchanged

### App.tsx (new — router + landing)

    function App() {

### vite.config.ts

    base: process.env.VITE_BASE_PATH || '/',

Default base is '/' — this is what npm run dev and npm run build use.
For GitHub Pages deploy, the predeploy script sets VITE_BASE_PATH=/planets/.

In package.json, change:
    "predeploy": "npm run build"
to:
    "predeploy": "cross-env VITE_BASE_PATH=/planets/ npm run build"

Or simpler (works on bash, which is our shell):
    "predeploy": "VITE_BASE_PATH=/planets/ npm run build"

So the workflow is:
    npm run dev        → localhost:3001/ (no /planets/)
    npm run build      → static site at /
    npm run deploy     → runs predeploy (builds with /planets/), then gh-pages pushes

### LandingPage.tsx

Simple component with three links/buttons:
    - Event Chart → /event
    - Natal Chart → /natal
    - Return Chart → /return (disabled/coming soon for now)

Uses react-router-dom's <Link> component so navigation is client-side.

## What moves where

From current App.tsx into the hooks:
    - selectedCity, setSelectedCity          → hook
    - selectedDate, setSelectedDate          → hook
    - currentTimezone (useMemo)              → hook
    - pickerBar JSX                          → hook's PickerBar component
    - modal INNER content (pickers only)     → hook's WelcomeContent component
    NOTE: WelcomeModal chrome (backdrop blur, borders, positioning, proceed button)
    stays in SingleChartPage. The hook only provides the interactive content inside it.

TODO after implementation: pickerBar should be wrapped in a Module. Fix this later.

Stays in SingleChartPage.tsx:
    - All settings store reads
    - All chart computation (useEventChartPositions, useAspects, rulershipGraph)
    - All layout logic (responsive breakpoints, sidebar zoom)
    - All extracted component instances (aspectMenuModule, planetInfoModule, etc.)
    - highlightedAspect, menuOpen, showModal, showScrollHint, tableScrollRef
    - highlightedNode, selectedNode
    - All three layout branches
    - useWindowWidth hook (stays at top of same file)

## Order of operations

1. Install react-router-dom
2. Create src/hooks/ folder
3. Write useEventChartInputs and useNatalChartInputs hooks
4. Rename App.tsx → ui/SingleChartPage.tsx, refactor to accept useChartInputs prop
5. Write new App.tsx (router)
6. Write LandingPage.tsx
7. Update main.tsx (BrowserRouter)
8. Update vite.config.ts (env-based base path)
9. Verify all three routes work
